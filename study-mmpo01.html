Unit 1: Operations Research — An Overview

▶
Introduction to Operations Research
▶
OR Phases and Model Building
Definition

Operations Research: Application of scientific methods to problems involving control of organized systems for management decision-making.

Mathematical Model: Simplified representation of a real-world system using mathematical symbols.

Objective Function: Mathematical expression to be maximized or minimized.

Constraints: Limitations on decision variables (resources, capacity, demand).

Core Concepts

  • OR = Scientific method for decision-making using mathematical models
  • Originated in WWII for military logistics optimization
  • Interdisciplinary: mathematics, statistics, engineering, economics
  • Phases: Problem Identification → Model Construction → Solution → Validation → Implementation
Real-World Example

Manufacturer deciding optimal product mix to maximize profit given limited raw materials, labor, and machine capacity.

Exam Tip

Know the difference between deterministic and stochastic models. Examiners frequently ask about OR phases and model characteristics.

Memory Aid

MODE-SIM — Model, Objective, Decision variables, Environment, Solution, Implementation, Monitoring

✅ Unit 1 Summary

  • OR uses mathematical models for optimal decisions
  • Interdisciplinary approach combining math, stats, engineering, economics
  • Five phases: Identify → Model → Solve → Validate → Implement

Unit 2: Linear Programming — Formulation & Graphical Method

▶
LP Formulation & Graphical Method
▶
LP Special Cases
Definition

Linear Programming: Mathematical technique for optimizing a linear objective function subject to linear constraints.

Feasible Solution: Solution satisfying all constraints.

Optimal Solution: Feasible solution that optimizes the objective function.

Slack: Unused resource (for ≤ constraints). Surplus: Excess over minimum (for ≥ constraints).

Shadow Price: Additional value from one more unit of a resource.

Core Concepts

  • LP = Optimization of linear objective function subject to linear constraints
  • Assumptions: Proportionality, Additivity, Divisibility, Certainty
  • Graphical method works for 2 decision variables only
  • Optimal solution lies at a corner point of the feasible region
Standard Form: Maximize Z = c1*x1 + c2*x2 Subject to: a11*x1 + a12*x2 ≤ b1 a21*x1 + a22*x2 ≤ b2 x1, x2 ≥ 0

Special Cases

  • Infeasible: No solution satisfies all constraints
  • Unbounded: Objective can increase infinitely
  • Multiple Optimal: Two corner points give same optimal value
  • Degenerate: A basic variable = 0 at a corner point
Real-World Example

A bakery makes cakes (profit Rs 200) and pastries (profit Rs 100). Each cake needs 2 eggs, 3 cups flour; each pastry needs 1 egg, 2 cups flour. With 20 eggs and 30 cups flour available, LP graphical method finds optimal product mix.

Exam Tip

Always formulate the problem first. Examiners give marks for correct formulation even if graphical solution has errors.

Memory Aid

FP-CP-SO — Formulate problem, Plot constraints, find Corner points, Select Optimal

✅ Unit 2 Summary

  • LP optimizes linear objective function subject to linear constraints
  • Graphical method for 2 variables, Simplex for multiple
  • Special cases: Infeasible, Unbounded, Multiple Optimal, Degenerate

Unit 3: Simplex Method

▶
Simplex Method Explained
▶
Simplex Tableau Example
Definition

Simplex Method: Iterative algorithm moving along edges of feasible polyhedron from vertex to adjacent improved vertex.

Basic Variable: Variable in current solution (has a column in basis).

Non-Basic Variable: Variable not in current solution (= 0).

Pivot Element: Intersection of entering column and leaving row.

Core Concepts

  • Algebraic method for solving LP with any number of variables
  • Iterative: moves from one basic feasible solution to an improved one
  • Uses tableau format for systematic computation
  • Stops when all Zj - Cj ≥ 0 (for maximization)

Simplex Algorithm Steps

  1. Convert to standard form (add slack/surplus/artificial variables)
  2. Set up initial tableau
  3. Identify entering variable (most negative Zj - Cj)
  4. Identify leaving variable (minimum ratio test: bi/aik)
  5. Pivot (Gauss-Jordan elimination)
  6. Repeat until optimal

Big-M vs Two-Phase Method

  • Big-M: Add penalty -M to artificial variables in objective
  • Two-Phase: Phase 1 minimizes sum of artificials; Phase 2 optimizes original objective
Real-World Example

A furniture manufacturer wants to maximize profit from tables and chairs given constraints on wood, labor, and machine hours. Simplex finds the optimal production mix that satisfies all constraints.

Exam Tip

Practice 3-4 simplex numericals. Common mistakes: wrong pivot selection, arithmetic errors in row operations.

Memory Aid

SE-LE-PI-R — Select Entering variable, Leaving variable, Pivot, Repeat

✅ Unit 3 Summary

  • Simplex iterates from vertex to improved vertex on feasible polyhedron
  • Uses tableau format with Zj - Cj optimality check
  • Big-M and Two-Phase methods handle artificial variables

Unit 4: Duality & Sensitivity Analysis

▶
Duality in LP
▶
Sensitivity Analysis
Definition

Range of Optimality: Range over which objective coefficients can change without changing optimal basis.

Range of Feasibility: Range over which RHS can change without changing basis (shadow prices remain valid).

Core Concepts

  • Every LP (primal) has a corresponding dual problem
  • Dual provides economic interpretation (shadow prices)
  • Strong duality: Optimal primal value = Optimal dual value
  • Sensitivity analysis examines how parameter changes affect optimal solution

Primal-Dual Relationships

Objective coefficientsRHS values
RHS valuesObjective coefficients
Constraint type (≤)Variable (≥ 0)
Variable (≥ 0)Constraint type (≥)

Complementary Slackness

  • If primal constraint not binding → corresponding dual variable = 0
  • If dual constraint not binding → corresponding primal variable = 0
Real-World Example

A company uses shadow prices to decide whether to buy additional raw materials. If shadow price of material A is Rs 50/kg but market price is Rs 40/kg, buying more is profitable.

Exam Tip

Know primal-dual conversion rules. Sensitivity questions often ask "what if" scenarios.

  • Every primal LP has a dual providing shadow prices
  • Complementary slackness links primal and dual solutions
  • Sensitivity analysis tests robustness of optimal solution

Unit 5: Transportation Problem

▶
Transportation Problem — VAM Method
▶
MODI Method for Optimality
Definition

Transportation Problem: Optimization to find minimum cost shipping schedule from m sources to n destinations.

Degenerate Solution: BFS with fewer than m+n-1 positive cells.

MODI Method: Computes ui and vj values to test optimality and improve solutions.

Core Concepts

  • Special LP for optimally transporting goods from sources to destinations
  • Minimizes total transportation cost
  • Must be balanced (total supply = total demand); add dummy if unbalanced
  • Methods: North-West Corner, Least Cost, Vogel’s Approximation (VAM) for initial BFS; MODI for optimality

VAM Steps

  1. Calculate penalty for each row/column (difference between two lowest costs)
  2. Allocate to lowest cost cell in row/column with highest penalty
  3. Cross out satisfied row/column
  4. Repeat until all allocations made
Real-World Example

A company has 3 factories (supply: 100, 150, 200 units) and 4 warehouses (demand: 80, 120, 130, 120 units). Transportation costs vary by route. VAM finds initial allocation, MODI optimizes to minimize total shipping cost.

Exam Tip

Always check for degeneracy. If basic cells < m+n-1, add epsilon to a non-basic cell with lowest cost.

Memory Aid

BL-VAM-MODI — Balance, Initial solution (VAM), Optimize (MODI), Degeneracy check, Iterate

✅ Unit 5 Summary

  • Transportation minimizes cost from sources to destinations
  • VAM gives best initial solution, MODI tests optimality
  • Used by Indian Oil, Reliance for logistics optimization

Unit 6: Assignment Problem

▶
Hungarian Method
▶
Assignment Problem Variants
Definition

Assignment Problem: Special case of transportation where each source is assigned to exactly one destination to minimize total cost.

Hungarian Method: Algorithm using row and column reductions to find optimal one-to-one assignment.

Core Concepts

  • Special case of transportation: each source assigned to exactly one destination
  • Solved using Hungarian Method
  • Minimization: subtract row min, then column min, cover zeros with minimum lines

Hungarian Method Steps

  1. Subtract row minimums from each row
  2. Subtract column minimums from each column
  3. Cover all zeros with minimum number of lines
  4. If lines = n: optimal. Else: find smallest uncovered element, subtract from uncovered, add to intersections
  5. Repeat

Variants

  • Maximize profit: Subtract all elements from max element
  • Unbalanced: Add dummy row/column
  • Restricted: Assign very large cost (M) to forbidden assignments
Real-World Example

A hospital assigns 4 nurses to 4 wards to minimize total patient complaints. The cost matrix shows complaint scores for each nurse-ward combination, solved by Hungarian method.

Exam Tip

Hungarian method is always asked. Practice the line-drawing step carefully.

Memory Aid

RCL-CEI-AL — Row min, Column min, Cover zeros, Equal lines = optimal, Increase zeros, Assign Lines

✅ Unit 6 Summary

  • Assignment assigns tasks one-to-one to minimize cost
  • Hungarian method is the optimal solution technique
  • Used in job assignment, machine allocation, resource matching

Unit 7: Integer & Goal Programming

▶
Branch and Bound Method
▶
Goal Programming Introduction
Definition

Integer Linear Programming (ILP): LP where variables are restricted to integer values.

Branch and Bound: Tree-based algorithm dividing feasible region into subproblems.

Goal Programming: Extension of LP minimizing deviations from multiple target goals.

Core Concepts

  • Integer Programming: Some or all variables must be integers
  • Branch and Bound: Systematic enumeration using LP relaxations
  • Goal Programming: Satisficing multiple conflicting objectives with priorities
Goal Programming Formulation: Minimize Z = P1(d1- + d1+) + P2(d2- + d2+) Subject to: f(x) + d- - d+ = b (goal constraint) x, d-, d+ ≥ 0 Where P1 >> P2 (lexicographic priority)
Real-World Example

A logistics company uses integer programming to decide which warehouses to open (binary: 0 or 1) to minimize total cost while serving all demand regions. Goal programming balances minimizing cost with maximizing customer satisfaction.

Exam Tip

Understand when to use IP vs LP relaxation. Know difference between goal constraints and hard constraints.

Memory Aid

BGP-SDP — Branch and Bound, Goals with Priorities, Satisficing, Deviation variables, Penalty

✅ Unit 7 Summary

  • Integer programming: discrete variables, solved by Branch and Bound
  • Goal programming handles multiple conflicting objectives with priorities
  • Deviational variables (d+, d-) measure goal achievement

Unit 8: Queuing Theory

▶
Queuing Theory Basics
▶
M/M/1 Queue Model
▶
Little's Law Explained
Definition

Kendall’s Notation: A/B/c/K/N/D — Arrival/Service/Servers/Capacity/Population/Discipline.

Utilization Factor: rho = lambda/mu (must be < 1 for stable system).

Core Concepts

  • Study of waiting lines to optimize service systems
  • Trade-off: Cost of waiting vs cost of providing service
  • Poisson arrivals + Exponential service = M/M/1 or M/M/c models
M/M/1 Formulas: Utilization: rho = lambda/mu Avg in system: L = lambda/(mu - lambda) Avg in queue: Lq = lambda² / [mu(mu - lambda)] Avg time in system: W = 1/(mu - lambda) Avg time in queue: Wq = lambda / [mu(mu - lambda)] P(n customers): Pn = (1 - rho) × rho&supn; Idle probability: P0 = 1 - rho Little’s Law: L = lambda × W, Lq = lambda × Wq
Real-World Example

A bank teller counter: customers arrive at 10/hour (Poisson), service takes 4 minutes on average (Exponential). Using M/M/1: rho = 10/15 = 0.67, L = 2 customers in system, W = 12 min average time.

Exam Tip

M/M/1 formulas are always asked. Remember Little’s Law works for ALL queuing models.

Memory Aid

ALQ-ULW — Arrival rate, Queue length, Utilization, Little’s Law, Waiting time

✅ Unit 8 Summary

  • Queuing optimizes service systems by balancing costs
  • Little’s Law: L = lambda × W
  • Used in banks, hospitals, call centers, traffic management

Unit 9: Game Theory

▶
Game Theory Introduction
▶
Saddle Point & Mixed Strategy
Definition

Saddle Point: Cell that is minimum in its row and maximum in its column.

Mixed Strategy: Players randomize with specific probabilities.

Value of Game: Expected payoff when both play optimally.

Core Concepts

  • Mathematical models of conflict and cooperation between rational players
  • Two-person zero-sum game: one player’s gain = other’s loss
  • Saddle point = equilibrium (if exists); otherwise use mixed strategies

Saddle Point Method

  1. Find row minimums (maximin)
  2. Find column maximums (minimax)
  3. If maximin = minimax: saddle point exists
Mixed Strategy (2×2): p1 = (d - c) / [(a + d) - (b + c)] q1 = (d - b) / [(a + d) - (b + c)] Value = (ad - bc) / [(a + d) - (b + c)]
Real-World Example

Two competing airlines (A and B) choose between high or low fares. Payoff matrix shows profits for each combination. Saddle point exists at (Low, Low) with value Rs 5 crore each — Nash equilibrium.

Exam Tip

Always check for saddle point first. For dominance, eliminate dominated strategies to reduce matrix.

Memory Aid

SD-MP-DV — Saddle point check, Mixed strategy Probabilities, Dominance, Value of game

✅ Unit 9 Summary

  • Game theory analyzes strategic decisions in competition
  • Zero-sum: one’s gain = other’s loss
  • Nash equilibrium: no unilateral improvement possible

▶
Simulation in OR
Definition

Simulation: Imitation of a real-world system’s behavior over time using a mathematical model.

Monte Carlo Technique: Uses random sampling to obtain numerical results for probabilistic problems.

Core Concepts

  • Imitation of real-world system using mathematical models

Steps

Define problem → Build model → Generate random numbers → Run simulation → Analyze output → Validate

An airline uses Monte Carlo simulation to model flight delays — random variables for weather, maintenance, and crew availability help estimate probability of on-time performance over 1000 simulated days.

Unit 11: Decision Theory

▶
Decision Theory & EMV
▶
Decision Trees
Definition

Decision Theory: Framework for making rational choices under conditions of certainty, risk, or uncertainty.

Expected Monetary Value (EMV): Weighted average of payoffs using probabilities as weights.

Expected Value of Perfect Information (EVPI): Maximum amount a decision-maker should pay for perfect information about future states.

Core Concepts

  • Framework for decisions under uncertainty
  • Criteria: Maximin (pessimistic), Maximax (optimistic), Minimax Regret, EMV

Decision Criteria

CriterionApproachBest For
MaximinBest of worst outcomesRisk-averse
MaximaxBest of best outcomesRisk-seeking
EMVBest expected valueKnown probabilities
Minimax RegretMinimize max regretConservative
EMV and EVPI: EMV(Ai) = Sum(Pj × Payoff(Ai, Sj)) EVPI = EMV(with perfect info) - EMV(without perfect info)
Real-World Example

A farmer decides whether to plant wheat, rice, or corn based on weather probabilities. EMV calculations show wheat has highest expected profit (Rs 2.5 lakh) vs rice (Rs 2.1 lakh) vs corn (Rs 1.8 lakh). EVPI = Rs 0.3 lakh — worth paying for a reliable weather forecast.

Exam Tip

Always calculate EVPI. Decision tree problems require backward induction.

Memory Aid

MEML-PI — Maximin, EMV, Maximax, Laplace, Perfect Information value

✅ Unit 11 Summary

  • Decision theory provides framework for rational choices under uncertainty
  • EMV uses probability-weighted payoffs
  • EVPI quantifies value of perfect information

Unit 12: Network Analysis (PERT/CPM)

▶
PERT/CPM Full Tutorial
▶
Network Analysis & Crashing
Definition

Critical Path: Longest path through the network; determines minimum project duration.

Slack/Float: Maximum time an activity can be delayed without delaying the project (Slack = LS - ES).

PERT Estimate: Weighted average time: te = (a + 4m + b) / 6, where a=optimistic, m=most likely, b=pessimistic.

Core Concepts

  • CPM: Deterministic times; find longest path = critical path
  • PERT: Probabilistic times (optimistic, most likely, pessimistic)
  • Slack = Latest Start - Earliest Start
PERT Time Estimate: te = (a + 4m + b) / 6 Variance: sigma² = [(b - a) / 6]² Z = (Ts - Te) / sqrt(sum of sigma² on critical path) Forward Pass: ES(j) = max[ES(i) + Duration(i,j)] Backward Pass: LF(i) = min[LS(j)]

Crashing Steps

  1. Identify critical path
  2. Select critical activity with lowest crash cost per unit time
  3. Crash by one unit
  4. Recalculate critical path
  5. Repeat until target reached
Real-World Example

A software company planning a product launch uses PERT/CPM to schedule design (10 days), development (30 days), testing (15 days), and deployment (5 days). Critical path is Design → Development → Testing → Deployment = 60 days minimum.

Exam Tip

Draw network diagram first. For PERT, calculate probability using Z-score.

Memory Aid

FBC-CCP — Forward pass, Backward pass, Critical path, Crashing, Cost, Probability

✅ Unit 12 Summary

  • PERT handles uncertainty, CPM uses deterministic times
  • Critical path = longest path = minimum project duration
  • Crashing reduces duration by adding resources to critical activities

Unit 13: Dynamic Programming

▶
Dynamic Programming Explained
▶
Knapsack Problem DP
Definition

Stage: Each step in sequential decision process.

State: Description of system at any stage.

Principle of Optimality: An optimal policy has the property that whatever the initial state and decision, remaining decisions must be optimal for the resulting state.

Core Concepts

  • Breaks complex problems into simpler overlapping subproblems
  • Principle of Optimality: optimal solution contains optimal sub-solutions
  • Works backward from final stage to first

Applications: Resource allocation, shortest path, inventory, scheduling

Real-World Example

A delivery truck with 10-ton capacity must choose from packages with different weights and values. Dynamic programming finds the combination that maximizes total value without exceeding capacity (knapsack problem).

Exam Tip

Define stages, states, and decision variables clearly. Always work backward.

Memory Aid

SSD-BW — Stages, States, Decision variables, Backward recursion, Work forward to verify

✅ Unit 13 Summary

  • DP breaks problems into overlapping subproblems
  • Uses backward induction from last stage to first
  • Applied in shortest path, inventory, resource allocation

Unit 14: Non-Linear Programming & Metaheuristics

▶
KKT Conditions Explained
▶
Genetic Algorithm Tutorial
Definition

NLP: Objective or constraints are non-linear. KKT conditions for constrained NLP.

Metaheuristics: GA (Genetic Algorithm), Simulated Annealing, Tabu Search.

KKT Conditions (for min f(x) subject to g(x) ≤ 0)

  1. grad(f) + mu × grad(g) = 0
  2. mu ≥ 0
  3. mu × g(x) = 0 (complementary slackness)
  4. g(x) ≤ 0

Genetic Algorithm Components

Encoding (chromosomes), Fitness function, Selection, Crossover, Mutation

Real-World Example

A telecom company optimizes cell tower placement (non-linear: signal strength varies non-linearly with distance). Genetic Algorithm evolves candidate solutions through generations until coverage is maximized at minimum cost.

Exam Tip

Know KKT conditions conceptually. For metaheuristics, understand exploration vs exploitation trade-off.

Memory Aid

KKT-GCSM — KKT conditions, GA: Chromosome, Selection, Crossover, Mutation

✅ Unit 14 Summary

  • NLP: non-linear objective or constraints, solved by KKT conditions
  • Genetic Algorithm: evolutionary approach with selection, crossover, mutation
  • Metaheuristics for complex problems without analytical solutions

Unit 15: Network Analysis — Advanced (Resource Leveling & Time-Cost Trade-Off)

▶
Resource Leveling & Crashing
▶
Time-Cost Trade-Off
Definition

Resource Leveling: Technique to resolve resource conflicts by adjusting start/finish dates within float.

Cost Slope: Additional cost per unit time reduction for an activity.

Project Crashing: Compressing schedule by adding resources to critical activities at minimum cost.

Indirect Costs: Overhead costs that increase with project duration (office rent, supervision).

Core Concepts

  • Resource Leveling: Adjusting schedule to smooth resource usage without changing project duration
  • Time-Cost Trade-off (Crashing): Reducing project duration at minimum additional cost
  • Normal Time/Cost: Standard duration and cost for an activity
  • Crash Time/Cost: Minimum possible duration and associated cost
Cost Slope = (Crash Cost - Normal Cost) / (Normal Time - Crash Time) Crashing Procedure: 1. Identify critical path 2. Calculate cost slope for each critical activity 3. Select activity with LOWEST cost slope on critical path 4. Crash by minimum of: available crash time, required reduction 5. Recalculate critical path (may shift!) 6. Stop when: target reached OR all activities at crash time OR cost of crashing > savings from indirect costs
Real-World Example

Construction project delayed by 2 weeks. Crashing foundation work (cost slope Rs 5,000/day) is cheaper than steel erection (Rs 15,000/day). Optimal crash balances direct + indirect costs.

Exam Tip

Always draw the time-cost curve. Numerical on crashing with 3-4 activities is very common. Remember: after each crash, re-check the critical path.

Memory Aid

CST-RCI — Cost Slope lowest first, Target duration, Recalculate path, Indirect cost balance

✅ Unit 15 Summary

  • Resource leveling smooths resource usage within float
  • Crashing reduces duration at minimum cost using cost slope
  • Optimal crash point balances direct and indirect costs

Unit 16: Advanced Metaheuristics & Modern OR Techniques

▶
PSO & ACO Algorithms
▶
Multi-Objective Optimization
Definition

Pareto Optimal Solution: Solution where no objective can be improved without worsening another.

Pareto Front: Set of all Pareto optimal solutions.

Swarm Intelligence: Collective behavior of decentralized agents following simple rules.

Pheromone Trail: Chemical signal left by ants guiding subsequent ants to food sources.

Core Concepts

  • Particle Swarm Optimization (PSO): Swarm intelligence mimicking bird flocking behavior
  • Ant Colony Optimization (ACO): Uses pheromone trails to find shortest paths
  • Multi-Objective Optimization: Optimizing 2+ conflicting objectives simultaneously (Pareto front)
  • Robust Optimization: Solutions that remain feasible under uncertainty
PSO Algorithm: Initialize particles with random positions and velocities Repeat: For each particle: Evaluate fitness Update personal best (pbest) Update global best (gbest) Update velocity: v = w*v + c1*r1*(pbest-x) + c2*r2*(gbest-x) Update position: x = x + v Until convergence

Real-World Example

Vehicle routing problem solved by ACO (Google Maps). Portfolio optimization with risk-return trade-off solved by multi-objective PSO.

Exam Tip

Know the difference between single-objective and multi-objective optimization. Pareto front diagrams are frequently asked. Understand when to use PSO vs ACO vs GA.

✅ Unit 16 Summary

  • PSO: particles update velocity using personal best and global best positions
  • ACO: ants deposit pheromones; shortest path gets most pheromone
  • Pareto front: set of solutions where no objective improves without worsening another

Model Answer Structure: LP Formulation (10 marks)

  1. Identify decision variables (2 marks): Let x1 = units of product A, x2 = units of product B
  2. Write objective function (2 marks): Maximize Z = 5x1 + 4x2 (profit per unit)
  3. Write constraints (3 marks): 2x1 + 3x2 <= 120 (raw material), x1 + x2 <= 60 (labor), x1, x2 >= 0
  4. Plot graph and identify feasible region (2 marks): Shade area satisfying all constraints
  5. Evaluate corner points (1 mark): Calculate Z at each corner point, select maximum

Model Answer Structure: Simplex Method (15 marks)

  1. Convert to standard form (2 marks): Add slack variables, set up initial tableau
  2. Initial tableau (3 marks): Identify basis, calculate Zj and Cj-Zj
  3. Iteration 1 (4 marks): Select entering variable (most negative Cj-Zj), leaving variable (min ratio), pivot
  4. Iteration 2 (4 marks): Repeat until all Cj-Zj >= 0
  5. Optimal solution (2 marks): Read solution from final tableau, state optimal Z

Model Answer Structure: Transportation (10 marks)

  1. Check balance (1 mark): Total supply vs total demand, add dummy if needed
  2. Initial solution by VAM (4 marks): Calculate penalty for each row/column, allocate to lowest cost cell in highest penalty row/column
  3. Optimality check by MODI (4 marks): Calculate ui, vj for occupied cells, compute dij for unoccupied cells
  4. Optimal solution (1 mark): All dij >= 0, calculate total transportation cost

Model Answer Structure: Queuing Theory (10 marks)

  1. Identify model (2 marks): M/M/1, M/M/c, etc. State arrival rate (lambda), service rate (mu)
  2. Calculate utilization (2 marks): rho = lambda/mu, check stability (rho < 1)
  3. Calculate performance measures (4 marks): L = lambda/(mu-lambda), Lq = rho*L, W = 1/(mu-lambda), Wq = rho*W
  4. Interpret results (2 marks): Average queue length, waiting time, system performance

Model Answer Structure: PERT/CPM (15 marks)

  1. Draw network (2 marks): Activities, dependencies, node numbering
  2. Forward pass (3 marks): Calculate ES, EF for all activities
  3. Backward pass (3 marks): Calculate LS, LF for all activities
  4. Identify critical path (2 marks): Activities with zero slack, longest path
  5. Calculate project duration (1 mark): Sum of critical path durations
  6. Crashing (4 marks): Calculate crash cost slope, crash critical activities, recalculate

Key Formulas Quick Reference

QUEUING THEORY: rho = lambda/mu (utilization) L = lambda/(mu - lambda) (avg in system) Lq = lambda^2/[mu(mu-lambda)] (avg in queue) W = 1/(mu - lambda) (time in system) Wq = lambda/[mu(mu-lambda)] (time in queue) Little's Law: L = lambda * W, Lq = lambda * Wq PERT: te = (a + 4m + b) / 6 Variance = [(b - a) / 6]^2 Z = (Ts - Te) / sqrt(sum of variances on critical path) GAME THEORY: Mixed strategy for Player 1: p = (d - c) / (a + d - b - c) Mixed strategy for Player 2: q = (d - b) / (a + d - b - c) Game value: v = (ad - bc) / (a + d - b - c) DECISION THEORY: EMV = sum(probability x payoff) EVPI = Expected with perfect info - Best EMV EOL = Expected Opportunity Loss TRANSPORTATION: MODI: dij = cij - (ui + vj) for unoccupied cells Crash cost slope = (Crash cost - Normal cost) / (Normal time - Crash time)
