Detailed Explanation: Memory Hierarchy

The memory hierarchy is designed to balance speed and cost. Registers are the fastest but smallest (nanoseconds, few KB). Cache memory (L1, L2, L3) sits between CPU and RAM, storing frequently accessed data. RAM (main memory) holds currently running programs. Secondary storage (HDD/SSD) provides permanent storage. The hierarchy ensures the CPU always has data available at the speed it needs.

Virtual memory extends RAM by using disk space as an overflow. When RAM is full, less-used data is "swapped" to disk. This allows running programs larger than physical RAM, but with a performance penalty since disk access is 1000x slower than RAM.

⚠ Exam Tip

Difference between Hub (broadcast) vs Switch (multicast) vs Router (inter-network) is a frequent question. Memory capacity conversions: 1 KB = 1,024 bytes, 1 MB ≈ 1 million, 1 GB ≈ 1 billion.

Detailed Explanation: Compiler vs Interpreter

A compiler reads the entire source code and translates it into machine code in one pass, creating an executable file. This makes compiled programs run faster, but compilation takes time. If there's an error, the compiler reports all errors at the end.

An interpreter reads and executes source code line by line. It doesn't create an executable — the source code itself is the program. This makes debugging easier (errors reported immediately) but execution is slower because each line must be translated every time it runs.

Java uses a hybrid approach: the compiler creates bytecode (.class files), then the JVM interprets or JIT-compiles the bytecode. This gives "write once, run anywhere" portability.

Detailed Explanation: OSI vs TCP/IP

The OSI model has 7 layers and is a theoretical framework for understanding network communication. TCP/IP has 4 layers and is the practical implementation used on the Internet. The mapping is: OSI Application/Presentation/Session = TCP/IP Application; OSI Transport = TCP/IP Transport; OSI Network = TCP/IP Internet; OSI Data Link/Physical = TCP/IP Network Access.

TCP (Transmission Control Protocol) provides reliable, ordered delivery with error checking. UDP (User Datagram Protocol) is faster but unreliable — used for streaming, gaming. IP (Internet Protocol) handles addressing and routing. Every device has a unique IP address (IPv4: 32-bit, IPv6: 128-bit).

Detailed Explanation: Anthony's Framework

Robert Anthony identified three levels of management planning and control: Strategic Planning (top management, long-term, 3-5 years), Management Control (middle management, medium-term, 1 year), and Operational Control (lower management, day-to-day). Each level requires different types of information — strategic needs external, summarized data; operational needs internal, detailed data.

A well-designed MIS provides the right information to the right person at the right time. It should be flexible, accurate, timely, and cost-effective. The system must support both routine reporting and exception-based alerting. Indian companies like Infosys and TCS use MIS dashboards that integrate data from 50+ countries for real-time management visibility.

⚠ Exam Tip

💡 Real-World Example

Infosys used SDLC for IRCTC ticketing system handling 1M+ bookings daily. TCS follows Agile SDLC for SBI’s YONO app serving 50M+ users.

Detailed Explanation: SDLC Deep Dive

The Waterfall model is sequential — each phase must complete before the next starts. This provides control and documentation but is lengthy and inflexible. The Fast SDLC (repository-based) allows phases to run in parallel with a shared data store, enabling backtracking and reusable knowledge.

Key success factors include proper requirements gathering, user involvement at all stages, realistic scheduling, and thorough testing. The biggest failure causes are inadequate requirements, poor communication, and scope creep.

Detailed Explanation: OOP Pillars

Java is platform-independent through bytecode compilation. The JVM interprets or JIT-compiles bytecode, enabling "write once, run anywhere." Python is interpreted line by line, making it easier to debug but slower in execution.

Detailed Explanation: Normalization

Normalization organizes data to reduce redundancy and improve integrity. 1NF eliminates repeating groups. 2NF removes partial dependencies. 3NF removes transitive dependencies. Each normal form builds on the previous one, progressively reducing data duplication and update anomalies.

Primary keys uniquely identify records. Foreign keys create relationships between tables. Candidate keys are potential primary keys. The DBA manages database design, implementation, and maintenance.

Normal FormRuleExample Fix
1NFNo repeating groups, atomic valuesSplit “Phone1, Phone2” into separate rows
2NF1NF + no partial dependencyRemove columns depending on part of composite key
3NF2NF + no transitive dependencyMove “Dept Name” (depends on Dept ID) to separate table

Detailed Explanation: Star vs Snowflake Schema

Star Schema has a central fact table connected to dimension tables in a denormalized structure. It's simpler and faster for queries but uses more storage. Snowflake Schema normalizes dimension tables into sub-dimensions, reducing redundancy but requiring more joins for queries.

OLAP operations include Slice (select single dimension), Dice (select sub-cube), Drill-down (more detail), Roll-up (less detail/aggregation), and Pivot (rotate dimensions). These enable multidimensional analysis of business data.

PivotRotate dimensions (change perspective)Rows: Products, Columns: Regions
